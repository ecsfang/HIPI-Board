# HIPI 1.7.2

The I2C chip list knows the MPU-6500, and the loop map says
"no accessory ID" for an instrument that has a device ID but no accessory ID.

## Downloads

| File | What it is |
|------|------------|
| `hipi_7_pico-v1.7.2.uf2` | The firmware for the 7" panel — drag it onto the Pico in BOOTSEL mode |
| `HIPI-SD-card-v1.7.2.zip` | Everything a new SD card needs — unzip it onto the card |
| `hipi_7_pico-v1.7.2.elf` | The firmware with debug symbols, for developers |

## New

- **MPU-6500** in the I2C chip list (TFI2C). It has its own entry because its
  temperature is not calculated like the MPU-6050's. A board sold as an
  MPU-6050 may carry an MPU-6500; TFI2C tells them apart by the WHO_AM_I
  register (0x70 or 0x68).

- **BMP390 and BMP388** (TFI2C `MT`/`MP`), measured with the chip's own
  calibration.
- **BME280, BME680 and BME688** (TFI2C `MT`/`MP`/`MH`): temperature, pressure
  and humidity (the BME680/BME688's gas sensor is not read).
- **BMP180 and BMP085** (TFI2C `MT`/`MP`): both have the chip ID 0x55 and are
  calculated the same way. They were found before, but not measured.

## Changed

- **Loop map: "no accessory ID".** A device that answers the controller's
  device ID request (SDI) but not its accessory ID request (SAI), such as the
  HP 3468, now shows its name and `no accessory ID` (`No ID` in the compact
  view; `none (SAI got no answer)` in the details box). `?` now only means
  that the question has not been asked yet.
- **The analyzer log** shortens an auto-addressing that changes nothing to
  `AUTO-ADDRESS (no change)`.
- **Manual:** the PCB section now says not to order the display with a font
  chip, because the maker then uses the RA8876 instead of the LT7683.

## Fixed

- The MPU-6050 entry no longer misreads an MPU-6500's temperature.

## Upgrading

- Flash `hipi_7_pico-v1.7.2.uf2` as usual. Your `CONFIG.TXT` keeps working.
- The SD card doesn't need to change. The chip list is built into the
  firmware; `i2c/chips.txt.example` on the card is only a reference.
