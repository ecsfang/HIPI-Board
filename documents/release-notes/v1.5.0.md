# HIPI 1.5.0

The plotter got its ERROR light and reports HP-GL errors as the real
HP 7470A does, and the Hardware test page now shows what your program
puts on the LEDs and pixels.

## Downloads

| File | What it is |
|------|------------|
| `hipi_7_pico-v1.5.0.uf2` | The firmware for the 7" panel — drag it onto the Pico in BOOTSEL mode |
| `HIPI-SD-card-v1.5.0.zip` | Everything a new SD card needs — unzip it onto the card |
| `hipi_7_pico-v1.5.0.elf` | The firmware with debug symbols, for developers |

## New

- **Plotter: the ERROR light.** Like the yellow light on the 7470A's front
  panel: when the plotter gets something it can't carry out, a small
  **ERROR n** light comes on at the top of the Plotter view.
  - **Touch it** to see what went wrong, e.g. *Error 2: wrong number of
    parameters -- SC 0,100* — the error and the command that caused it.
  - **Plotter menu → Errors** lists the last eight errors with their
    commands; **Clear error** puts the light out.
  - `OE` and `IN` put it out, as on the real plotter. Looking at it on HIPI
    doesn't clear it: the program still gets the error with `OE`.
  - While it's lit, the plotter's card in the **Loop map** has a yellow LED
    and the info box (top-left corner) says so.
- **Plotter: HP-GL errors as the manual has them** — error 1 (unknown
  instruction), 2 (wrong number of parameters: an odd number in
  `PA`/`PD`/`PU`/`PR`, `SI`/`SR`/`DI`/`DR` with one number, ...), 3 (out of
  range: `SP 40000`, `VS 100`, `DI 0,0`, `LT 200`, ...) and 6 (position
  overflow). `IM` (input mask) now chooses which errors count; as on the
  real plotter, error 6 doesn't by default. `AP AF AH EC VA VN` are
  accepted and ignored, without an error.
- **Plotter on HP-IL:** the device ID (`SDI`) is now `HP7470A`, as the real
  plotter's, and **Send status** (`SST`) answers the status byte.
- **Hardware test page shows your program.** When it opens it only looks:
  the LED buttons and the row of pixel circles show what `TFLEDS` and
  `TFPIXEL` drive — blinking, fading, effects, HP-IL traffic on LED 4 — so
  a program can be tried without LEDs or pixels fitted (**Fitted** *YES*;
  `0N8` from the HP-41 shows 8 pixels). A test of the page's own (an LED
  button, **Chase**, **Run**, a colour) takes them over as before; **Off**
  ends it and goes back to showing `TFLEDS` / `TFPIXEL`.
- **Demo:** an HP-GL error — the ERROR light comes on, is touched and says
  what went wrong, then `OE` puts it out.

## Fixed

- **Pixels:** a frame sent right after another one was lost — the pixels
  kept the first. Seen on the Hardware test page: the first touch on a
  colour lit the circles on the screen but not the pixels (the next one
  did). It could also hit a `TFPIXEL` command right after another. The
  pixels now get the pause they need between two frames.

## Changed

- An HP-41 program may now light the ERROR light where it didn't show
  anything before: HIPI checks HP-GL as the real plotter does. A few
  commands the real plotter rejects are now ignored as it does (e.g. `DI`
  or `SR` with one number, `LT 200`) — they used to be carried out.
- A program that looks for the plotter by its device ID gets `HP7470A`
  (it was `TFPLOT`).
- **Hardware test page:** the pixel circles run from right to left —
  pixel 1 on the right, as the pixels sit on the board. The button strip
  no longer comes up over the page (it covered the close **✕** and the
  pixels' **Off**); the **✕** closes the page.

## Upgrading

- Flash `hipi_7_pico-v1.5.0.uf2` as usual. Your `CONFIG.TXT` keeps working.
- The SD card doesn't need to change.
- hipiview: the one from 1.4.0 still works.
