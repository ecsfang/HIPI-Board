# HIPI 1.7.1

hipiview now keeps HIPI's clock right from the PC, to within a few
thousandths of a second. The clock screen saver draws its digits at once,
blinks its colon, and has a goose that crosses the screen once a minute.

## Downloads

| File | What it is |
|------|------------|
| `hipi_7_pico-v1.7.1.uf2` | The firmware for the 7" panel — drag it onto the Pico in BOOTSEL mode |
| `HIPI-SD-card-v1.7.1.zip` | Everything a new SD card needs — unzip it onto the card |
| `hipi_7_pico-v1.7.1.elf` | The firmware with debug symbols, for developers |

## New

- **The clock set from the PC.** With hipiview connected (**View** or
  **Control**), HIPI's clock chip is compared with the PC's clock as soon as
  the screen is in. If it is more than a quarter of a second off, or not set
  at all, hipiview sets it to within a few milliseconds. It checks again once
  a day, so summer and winter time come along. hipiview's title bar says what
  it did ("HIPI's clock is 3.2 s slow -- setting it", "... set from this PC
  -- now +0.002 s").
  - **Settings → Screen saver → Clock from PC**:
    - **Auto** (the default): hipiview sets the clock by itself.
    - **Ask**: HIPI asks first, on its screen.
    - **Off**: only when you choose **Set clock from PC**.
  - **Set clock from PC**, in the same menu and on the **Hardware test**
    page (the I2C card), sets the clock right now, whatever the setting.
  - hipiview doesn't set the clock by itself when the PC's own clock isn't
    synchronised (Linux: `timedatectl`). **Set clock from PC** still sets it.
  - This works with DS3231, DS1307 and PCF85063A chips. The PCF85063A is
    started at exactly the right moment, because writing its time doesn't
    restart its count of the second.
- **A goose on the clock.** It flies along the bottom of the clock screen
  saver, once a minute. At :00 it comes in on the left, at :30 it is in the
  middle, and it leaves on the right just as the next minute begins.
- **The colon blinks**: lit one second, dark the next.

## Changed

- **The clock's digits appear at once.** A new minute is drawn off-screen
  and copied in as a whole. Before, the digits were drawn row by row.
- **The device list** shows each device's address (AID) in decimal as well as
  in hex.
- `CONFIG.TXT`: new `clock_from_pc=auto|ask|off` (`auto` if it's missing).

## Fixed

- **Black squares on the cassette reels.** While the tape drive turned, the
  reels' spokes could briefly show as black squares on the panel. Each reel
  frame is now copied in one go.

## Under the hood

- **Plotter code split up.** `CPlotter` (`plotter.cpp`) now holds only the
  HP-IL device. The HP-GL interpreter (`hpgl.cpp`, with the HP 7470A model)
  and the plotter view (`plotterview.cpp`) are separate, so they can be
  reused by another plotter. Plots look the same as before.
- **The mirror protocol is now version 8 (CLOCK).** HIPI only sends clock
  reports when hipiview asks, so an older hipiview works as before.

## Upgrading

- Flash `hipi_7_pico-v1.7.1.uf2` as usual. Your `CONFIG.TXT` keeps working.
- The SD card doesn't need to change.
- **hipiview:** use the 1.7.1 version to have the clock set. hipiview 1.7.0
  works with this firmware as before, but doesn't set the clock. hipiview
  1.7.1 with older firmware asks nothing.
- Going back to 1.7.0: it ignores `clock_from_pc=`.
