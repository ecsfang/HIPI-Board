# HIPI 1.6.0

Files between the PC and HIPI's cassettes, through hipiview: drop a
cassette or an HP-41 program on the window and it goes onto HIPI's drive;
save a whole cassette, or a single file of it, on the PC. LED 3 can be the
plotter's ERROR light, and LED 4 now shows real HP-IL messages only.

## Downloads

| File | What it is |
|------|------------|
| `hipi_7_pico-v1.6.0.uf2` | The firmware for the 7" panel — drag it onto the Pico in BOOTSEL mode |
| `HIPI-SD-card-v1.6.0.zip` | Everything a new SD card needs — unzip it onto the card |
| `hipi_7_pico-v1.6.0.elf` | The firmware with debug symbols, for developers |

## New

- **A cassette from the PC.** With **Mirror to PC < Control >**, show the
  Tape view of a drive and drag a LIF volume (`.dat` / `.lif`) onto the
  hipiview window. hipiview asks first — **Put in** (the drive is empty)
  or **Replace** (the old file stays on the SD card) — then sends it. HIPI
  copies it to the `lif` folder and puts it in as if **OPEN** had been
  pressed and the file chosen: it waits until the drive is idle, so a
  command from the HP-41 is never cut.
- **An HP-41 program onto the cassette.** Drop a raw program (`.raw`, as
  V41, go41cv or lifutils' `lifget -r` make them) the same way: it is added
  to the cassette in the drive as a PGM41 file the HP-41 reads with `READP`
  — byte for byte what lifutils' `raw41lif` + `lifput` make.
  - Its name comes from the file's: upper case, letters and digits, at most
    10 (`vector-ops.raw` → `VECTOROPS`).
  - hipiview asks **Add**; if a file of that name is on the cassette,
    **Replace** or **Skip**.
  - An empty drive gets a new, empty cassette for it (`CASS01.DAT` …).
  - No room, or a full directory: said before anything is sent.
- **A file with its directory entry** (`NAME.lif`, as **Save on PC** or
  lifutils' `lifget` makes it) dropped on the window goes onto the cassette
  as it is — its own name and type: a write-all, key assignments, data, an
  HP-71 file …
- **Several files at once:** they are taken one after the other, each
  asked about. With more waiting, the question has a third button — **Add
  all** (never replaces anything) or **Replace all**. The title bar shows
  *file 2 of 5*, and a message at the end lists any that weren't sent.
- **A cassette to the PC.** **Save media on PC** in the Tape view's menu
  (shown while hipiview is connected, View or Control), or **M** in
  hipiview, sends the drive's cassette — with everything the HP-41 saved on
  it. hipiview opens the PC's **Save as** dialog with the name filled in, in
  the folder used last. HIPI reads it only while the drive is idle and
  starts over if the HP-41 writes to it meanwhile, so it's always one whole
  cassette. `hipiview --save-to DIR` saves without asking.
- **A single file to the PC.** Tap a file in the **Media map**: its box has
  **Save on PC**. Saved as lifutils saves files — an HP-41 program as
  `NAME.raw` (like `lifget -r`: the program and its checksum), anything
  else as `NAME.lif` (like `lifget`: its directory entry first, so it can
  be put back unchanged).
- **Media map:** files of the same kind one after the other (several
  programs) are told apart by a thin line in a slightly darker shade where
  one ends and the next begins — before, they looked like one big file.
  Very small files close together don't all get one, so the map stays calm.
- **LED 3: the plotter's ERROR light.** **Hardware test → Plotter error on
  LED 3** (*ON* by default): LED 3 lights while the plotter has an HP-GL
  error, like the yellow light on the HP 7470A, and goes out with `OE`,
  `IN` or **Clear error**. *OFF* leaves LED 3 to `TFLEDS` (which can still
  use it with *ON* — only an error coming or going switches it).
- **LED 4: HP-IL messages only.** **Hardware test → HP-IL on LED 4** now has
  three settings: *MESSAGES* (new, the default) flashes for commands,
  addressing and data and stays dark while the loop only idles; *ALL* is
  the old behaviour — every frame, so with an HP-41 or HP-71 switched on,
  which keep sending IDY frames, it looks lit all the time; *OFF* leaves
  LED 4 to `TFLEDS`.

## Fixed

- **HIPI stood still when the PC didn't answer through PILBox.** With pyILPER
  in `COFF`/`COFI`, HIPI waited for its answer to each frame with no time
  limit. If pyILPER stopped, hung or lost a byte, or the port closed at the
  wrong moment, HIPI stood still: no screen, no touch, no hipiview, and only
  a restart helped. HIPI now keeps running while it waits.
  - After **2 s** with no answer it drops the frame (the HP-41 shows
    `TRANSMIT ERR`), switches PILBox to `TDIS` and shows a warning.
  - The HP-41's next try works without the PC's devices.
  - When pyILPER starts again, everything carries on as usual.
- **hipiview read the whole screen again** — often when the button strip
  and a menu were opened, or a cassette was chosen. The first drawing after
  HIPI had been idle filled the mirror's buffer, and HIPI took the viewer's
  last answer (up to a second old) for "nobody's reading" and ended the
  session ("the link fell behind (ring full)" in the log). It now only
  gives up when the viewer is silent *while* HIPI waits.
- hipiview didn't know it was in **Control** on the first connection
  (HIPI didn't say so until the setting changed).
- hipiview's *Save as* dialog on Linux now fills in the file's name (zenity
  4 left it empty): GTK's own dialog is used when it's there.

## Changed

- **The first view after start-up** is now that of the first device on
  the loop (in loop order) that is switched on and has a view. Before, it was
  always the Display view, even with `TFDISPLAY` switched off. With no such
  device, HIPI starts with the **Loop map**. The same rule applies when HIPI
  can't go back to a view whose device has since been switched off.
- **hipiview waits longer before giving up on HIPI**: after 2.5 s of
  silence it asks "still there?" every second, and only after 7 s does it
  ask for the whole screen again. HIPI itself doesn't count a pause of its
  own (a long SD card access) against the viewer. The log notes such
  pauses: `Main loop: HP-IL took N ms`, `HIPI was busy for N ms`.
- `CONFIG.TXT`: `hpil_leds` is now `messages` / `all` / `off` (the old `1`
  and `0` are read as `all` and `off`); new `plotter_led=plotter|off`.
- The mirror protocol is version 7 (files both ways).

## Upgrading

- Flash `hipi_7_pico-v1.6.0.uf2` as usual. Your `CONFIG.TXT` keeps working.
- **LED 4:** your `CONFIG.TXT` most likely says `hpil_leds=1`, which is
  *ALL* — LED 4 then still looks lit with an HP-41 on. Tap **HP-IL on LED
  4** on the Hardware test page once (or write `hpil_leds=messages`).
- **LED 3** is the plotter's ERROR light from now on; if you use it with
  `TFLEDS`, that still works — or switch it **OFF** on the Hardware test
  page.
- The SD card doesn't need to change.
- **hipiview:** get 1.6.0 for the file transfers (drag and drop, **M**,
  **Save on PC**). An older hipiview still shows and controls the screen.
  On Linux the *Save as* dialog uses `python3-gi` / GTK 3 (on Ubuntu's
  desktop already), else `zenity` or `kdialog`.
- Going back to 1.5.0: it reads `hpil_leds=messages` as *OFF* — set it
  again on the Hardware test page.
